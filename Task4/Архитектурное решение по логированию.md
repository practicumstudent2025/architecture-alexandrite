# Архитектурное решение по логированию

## Анализ системы для логирования

### **Системы для сбора логов**:
- **Shop API** - логи заказов, загрузки файлов, ошибок пользователей
- **CRM API** - логи работы с клиентами, изменения статусов
- **MES API** - логи производства, расчетов стоимости, статусов заказов
- **RabbitMQ** - логи сообщений, очередей, ошибок доставки
- **Databases** - логи запросов, ошибок подключения
- **S3 Storage** - логи загрузки/скачивания файлов

### **Необходимые логи с уровнем INFO**:
- **Создание заказа**: время, user_id, order_id, статус
- **Изменение статуса заказа**: время, order_id, старый_статус, новый_статус
- **Загрузка файла**: время, user_id, file_name, file_size
- **Расчет стоимости**: время, order_id, duration, результат
- **Отправка сообщения**: время, queue_name, message_id, статус
- **Аутентификация**: время, user_id, результат
- **Ошибки API**: время, endpoint, error_code, user_id

### **Другие уровни логирования**:
- **DEBUG** - детальная отладка (только в dev/test)
- **WARN** - предупреждения о производительности, нестандартные ситуации
- **ERROR** - ошибки, не критичные для работы системы
- **FATAL** - критические ошибки, требующие немедленного вмешательства

## Мотивация

### **Проблемы**:
- Отсутствие видимости в работе системы
- Долгая диагностика проблем 
- Высокая нагрузка на поддержку
- Невозможность проактивного мониторинга

### **Решение**:
- Централизованное логирование всех систем
- Структурированные логи для быстрого поиска
- Автоматический анализ и алертинг
- Снижение времени диагностики

### **Влияние на метрики**:
- **MTTD (Mean Time to Detection)** - значительное снижение
- **MTTR (Mean Time to Resolution)** - существенное снижение
- **Support Tickets** - значительное снижение
- **Customer Satisfaction** - повышение
- **Development Velocity** - повышение

## Приоритизация систем

### **Первая очередь (критично)**:
1. **Shop API** - основной пользовательский интерфейс
2. **RabbitMQ** - критичная интеграция между системами
3. **MES API** - расчет стоимости (2-3 минуты обработки)

### **Вторая очередь (важно)**:
4. **CRM API** - управление заказами
5. **Databases** - проблемы с данными

### **Третья очередь (желательно)**:
6. **S3 Storage** - файловые операции

## Предлагаемое решение

### **Технологии**:
- **ELK Stack** - Elasticsearch, Logstash, Kibana
- **Filebeat** - сбор логов с серверов
- **Grafana** - визуализация и дашборды

### **Компоненты**:
- **Новые**: Elasticsearch, Logstash, Kibana, Filebeat
- **Доработка**: Shop API, CRM API, MES API, RabbitMQ

### **C4 диаграмма**: [alexandrit_logging_c4.drawio](alexandrit_logging_c4.drawio)
**Синие элементы**: Filebeat, Logstash, Elasticsearch, Kibana (логирование)
**Связи**: API → Filebeat → Logstash → Elasticsearch → Kibana

## Безопасность

### **Чувствительные данные**:
- **Маскирование**: пароли, токены, персональные данные
- **Шифрование**: логи в transit и at rest
- **Доступ**: Role-based (Support, Admin, Read-only)
- **Аудит**: логирование доступа к логам

### **Политики доступа**:
- **Support** - только ERROR и WARN логи
- **Admin** - все логи с маскированием чувствительных данных
- **Read-only** - только агрегированные данные

## Хранение логов

### **Структура индексов**:
- **shop-logs-YYYY.MM.DD** - логи Shop API
- **crm-logs-YYYY.MM.DD** - логи CRM API
- **mes-logs-YYYY.MM.DD** - логи MES API
- **rabbitmq-logs-YYYY.MM.DD** - логи RabbitMQ

### **Политики хранения**:
- **Retention**: 90 дней для INFO, 180 дней для ERROR
- **Размер**: ~50GB/день для всех систем
- **Архивирование**: старые логи в S3
- **Удаление**: автоматическое через 90/180 дней

## Анализ логов

### **Алертинг**:
- **High Error Rate** - > 5% ошибок за 10 минут
- **Slow Response** - > 5 секунд для критичных операций
- **Queue Backup** - > 1000 сообщений в очереди
- **Disk Space** - < 10% свободного места

### **Аномалии**:
- **DDoS Detection** - резкий рост запросов
- **Unusual Patterns** - нестандартное поведение пользователей
- **Resource Exhaustion** - высокое потребление ресурсов
- **Security Threats** - подозрительная активность

## Критерии выбора технологии

| Критерий | ELK Stack | OpenSearch | Splunk | Grafana Loki |
|----------|-----------|-------------|---------|--------------|
| **Лицензия** | Elastic License | Apache 2.0 | Проприетарная | Apache 2.0 |
| **Стоимость** | Бесплатно | Бесплатно | Дорого | Бесплатно |
| **Производительность** | Высокая | Высокая | Очень высокая | Средняя |
| **Масштабируемость** | Отличная | Отличная | Отличная | Хорошая |
| **Простота настройки** | Средняя | Средняя | Простая | Простая |
| **Экосистема** | Большая | Средняя | Очень большая | Растущая |
| **Поддержка** | Комьюнити | Комьюнити | Коммерческая | Комьюнити |

### **Выбор: ELK Stack**
**Плюсы**: Бесплатно, высокая производительность, большая экосистема, хорошая документация
**Минусы**: Сложность настройки, потребление ресурсов, лицензионные ограничения
