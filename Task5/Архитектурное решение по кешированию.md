# Архитектурное решение по кешированию

## Анализ системы для кеширования

### **Проблемные области**:
- **MES API** - медленная загрузка списка заказов
- **Shop API** - медленный расчет стоимости (2-3 минуты)
- **CRM API** - медленное обновление статусов заказов

### **Кандидаты для кеширования**:
- **Список заказов** - часто запрашивается операторами
- **Статусы заказов** - часто обновляются и читаются
- **Расчеты стоимости** - долгие вычисления (2-3 минуты)
- **Справочные данные** - редко изменяются

## Мотивация

### **Проблемы**: Низкая производительность MES, медленные расчеты, высокая нагрузка на БД, плохой UX

### **Решение**: Серверное кеширование (Redis) + клиентское кеширование (браузер)

### **Влияние на метрики**: Снижение Response Time, Database Load, повышение User Satisfaction, System Throughput

## Предлагаемое решение

### **Тип кеширования**: Серверное (Redis) + клиентское (браузер)

### **Паттерны кеширования**:
- **Cache-Aside** - список заказов, статусы (простота, контроль)
- **Write-Through** - обновление статусов (консистентность)
- **Refresh-Ahead** - расчеты стоимости (актуальность)

### **Стратегия инвалидации**: Комбинированная
- **TTL** - большинство данных (простота)
- **По ключу** - критичные изменения (консистентность)
- **Программная** - экстренные случаи (контроль)

## Технические детали

### **Redis конфигурация**: 4GB памяти, RDB + AOF, Master-Slave, настраиваемый TTL

### **Кешируемые данные**:
- **Список заказов**: 5 минут TTL
- **Статусы заказов**: 1 минута TTL
- **Расчеты стоимости**: 30 минут TTL
- **Справочники**: 1 час TTL

### **Мониторинг**: Hit Rate, Miss Rate, Memory Usage, Response Time

## Реализация

### **Этапы**: Redis → MES API → CRM API → Shop API → Мониторинг

### **Ожидаемые результаты**: Снижение времени загрузки с 10 сек до 1 сек, ускорение расчетов, снижение нагрузки на БД на 70%
