# Архитектурное решение по трейсингу

## Анализ системы для трейсинга

### Системы, требующие покрытия трейсингом

#### 🔴 **Критичные системы** (обязательно):
- **Shop API** - создание заказов, загрузка 3D-моделей
- **MES API** - расчет стоимости, обработка заказов
- **CRM API** - управление заказами, статусы
- **RabbitMQ** - передача сообщений между системами

#### 🟡 **Важные системы** (рекомендуется):
- **Shop Database** - хранение данных заказов
- **MES Database** - хранение данных расчетов
- **S3 Storage** - хранение 3D-моделей
- **Frontend Applications** - пользовательские действия (Vue.js, React)
- **Load Balancer/API Gateway** - маршрутизация запросов
- **Redis Cache** - кэширование расчетов стоимости
- **External APIs** - платежные системы, транспортные компании
- **Message Queues** - Dead Letter Queues, Retry Queues, Priority Queues
- **Database Operations** - Transaction Tracing, Query Performance, Connection Pooling
- **File Operations** - File Upload/Download, File Processing, File Storage
- **Circuit Breaker** - отслеживание состояния circuit breaker
- **Bulkhead Isolation** - отслеживание изоляции ресурсов
- **Rate Limiting** - отслеживание rate limiting
- **Health Checks** - отслеживание health checks

### Места, где заказ может "сломаться" или зависнуть

#### **1. Создание заказа (Shop API → CRM)**
- **Проблема**: Заказ создан, но не дошел до CRM
- **Причина**: Сбой в RabbitMQ, потеря сообщения
- **Трейсинг**: Отслеживание сообщения от Shop до CRM

#### **2. Расчет стоимости (CRM → MES)**
- **Проблема**: Заказ отправлен на расчет, но MES не отвечает
- **Причина**: Перегрузка MES, сбой в расчете
- **Трейсинг**: Отслеживание запроса к MES и времени обработки

#### **3. Обновление статуса (MES → CRM)**
- **Проблема**: Расчет выполнен, но статус не обновился
- **Причина**: Сбой в RabbitMQ, потеря сообщения
- **Трейсинг**: Отслеживание сообщения от MES до CRM

#### **4. Загрузка 3D-модели (Shop → S3)**
- **Проблема**: Файл загружен, но не обработан
- **Причина**: Сбой в S3, проблемы с сетью
- **Трейсинг**: Отслеживание загрузки и обработки файла

#### **5. Аутентификация и авторизация**
- **Проблема**: Пользователь не может войти в систему
- **Причина**: Сбой в аутентификации, истекшие токены
- **Трейсинг**: Auth запросы, токены, сессии

#### **6. Валидация данных**
- **Проблема**: Неверные данные заказа
- **Причина**: Ошибки валидации, некорректные 3D-модели
- **Трейсинг**: Валидация, ошибки данных

#### **7. Уведомления**
- **Проблема**: Пользователь не получил уведомление
- **Причина**: Сбой в email/SMS сервисе
- **Трейсинг**: Отправка уведомлений, доставка

#### **8. Каскадные сбои**
- **Проблема**: Сбой в одной системе влияет на другие
- **Причина**: MES падает → CRM не получает ответ → Shop показывает ошибку
- **Трейсинг**: Отслеживание каскадных эффектов

#### **9. Race Conditions**
- **Проблема**: Два оператора берут один заказ
- **Причина**: Одновременные операции конфликтуют
- **Трейсинг**: Отслеживание конкурентных операций

#### **10. Partial Failures**
- **Проблема**: Заказ создан, но статус не обновился
- **Причина**: Частичный сбой в системе
- **Трейсинг**: Отслеживание частичных операций

#### **11. Timeout Scenarios**
- **Проблема**: Операция превысила таймаут
- **Причина**: Медленная обработка, сбой сети
- **Трейсинг**: Отслеживание таймаутов

#### **12. Resource Exhaustion**
- **Проблема**: Недостаточно ресурсов для обработки
- **Причина**: Перегрузка системы, нехватка памяти
- **Трейсинг**: Отслеживание использования ресурсов

## Данные для трейсинга

### **Обязательные данные**:
- **Order ID** - уникальный идентификатор заказа
- **Trace ID** - идентификатор трейса для связывания операций
- **Span ID** - идентификатор отдельной операции
- **Parent Span ID** - связь с родительской операцией
- **Timestamp** - время выполнения операции
- **Service Name** - название сервиса (shop-api, mes-api, crm-api)
- **Operation Name** - название операции (create-order, calculate-price)
- **Status** - статус операции (success, error, timeout)
- **Duration** - время выполнения операции
- **Error Message** - сообщение об ошибке (если есть)

### **Бизнес-данные**:
- **User ID** - идентификатор пользователя
- **Order Status** - текущий статус заказа
- **File Size** - размер 3D-модели
- **Calculation Time** - время расчета стоимости
- **Queue Name** - название очереди RabbitMQ
- **Message ID** - идентификатор сообщения
- **Order Type** - тип заказа (B2C/B2B)
- **Priority** - приоритет заказа
- **Customer Tier** - уровень клиента
- **Geographic Location** - географическое положение

### **Технические данные**:
- **HTTP Method** - метод запроса (GET, POST, PUT)
- **HTTP Status** - код ответа (200, 500, 404)
- **Database Query** - SQL запрос к БД
- **Cache Hit/Miss** - попадание в кэш
- **Memory Usage** - использование памяти
- **CPU Usage** - использование CPU
- **Request ID** - идентификатор запроса
- **Correlation ID** - идентификатор корреляции
- **Transaction ID** - идентификатор транзакции
- **Retry Count** - количество повторных попыток
- **Session ID** - идентификатор сессии
- **IP Address** - IP адрес пользователя
- **User Agent** - браузер пользователя

### **Дополнительные метрики**:
- **Throughput** - пропускная способность
- **Latency P95/P99** - задержка операций
- **Queue Depth** - глубина очереди
- **Connection Pool** - пул соединений
- **Disk I/O** - операции с диском
- **Network I/O** - сетевые операции
- **Database Connections** - соединения с БД
- **Cache Size** - размер кэша
- **Order Value** - стоимость заказа
- **Processing Time** - время обработки
- **Success Rate** - процент успешных операций
- **Error Rate** - процент ошибок
- **Page Load Time** - время загрузки страницы
- **User Journey** - путь пользователя
- **Conversion Rate** - конверсия
- **Bounce Rate** - отказы

## Мотивация

### **Проблемы без трейсинга**:
- **Отсутствие видимости**: Невозможно понять, где застрял заказ
- **Долгая диагностика**: Часы на поиск проблемы
- **Потеря заказов**: Заказы "исчезают" в системе
- **Недовольство клиентов**: Жалобы на просроченные заказы
- **Потеря контрактов**: Крупные клиенты уходят

### **Что даст трейсинг**:
- **Полная видимость**: Видно весь путь заказа через систему
- **Быстрая диагностика**: Минуты вместо часов
- **Предотвращение потерь**: Заказы не теряются
- **Улучшение SLA**: Быстрое решение проблем
- **Доверие клиентов**: Стабильная работа системы

### **Ключевые метрики**:
1. **Mean Time to Detection (MTTD)** - время обнаружения проблемы
2. **Mean Time to Resolution (MTTR)** - время решения проблемы
3. **Order Completion Rate** - процент завершенных заказов
4. **Customer Satisfaction** - удовлетворенность клиентов
5. **Revenue Impact** - влияние на выручку

## Предлагаемое решение

### **Архитектура трейсинга**

#### **1. Distributed Tracing System**
- **Jaeger** - основная система трейсинга
- **OpenTelemetry** - стандарт для инструментации
- **Jaeger Collector** - сбор трейсов
- **Jaeger Query** - поиск и анализ трейсов
- **Jaeger UI** - веб-интерфейс для просмотра

#### **2. Инструментация приложений**
- **Java Spring Boot** (Shop API, CRM API):
  - Spring Cloud Sleuth
  - OpenTelemetry Java SDK
  - Автоматическая инструментация HTTP запросов
- **C# .NET** (MES API):
  - OpenTelemetry .NET SDK
  - ASP.NET Core инструментация
  - Кастомные трейсы для расчетов
- **RabbitMQ**:
  - RabbitMQ Tracing Plugin
  - Инструментация сообщений
  - Отслеживание очередей

#### **3. Хранилище трейсов**
- **Elasticsearch** - основное хранилище
- **Kibana** - визуализация и анализ
- **Retention Policy** - 30 дней для детальных трейсов
- **Sampling** - 10% для production, 100% для dev

#### **4. Мониторинг и алертинг**
- **Jaeger Alerts** - алерты на проблемы
- **Grafana Dashboards** - дашборды трейсинга
- **Prometheus Metrics** - метрики из трейсов
- **Slack Integration** - уведомления команде

### **Компоненты для внедрения**

#### **Новые компоненты**:
1. **Jaeger Collector** - сбор трейсов
2. **Jaeger Query** - поиск трейсов
3. **Jaeger UI** - веб-интерфейс
4. **Elasticsearch** - хранилище
5. **Kibana** - аналитика
6. **OpenTelemetry SDK** - инструментация

#### **Доработка существующих**:
1. **Shop API** - добавление трейсинга
2. **CRM API** - добавление трейсинга
3. **MES API** - добавление трейсинга
4. **RabbitMQ** - настройка трейсинга сообщений

### **Схема архитектуры**

#### **Основная схема** (красные элементы - новые компоненты):
```
[Shop API] --trace--> [Jaeger Collector] --> [Elasticsearch]
[CRM API] --trace--> [Jaeger Collector] --> [Kibana]
[MES API] --trace--> [Jaeger Collector] --> [Jaeger UI]
[RabbitMQ] --trace--> [Jaeger Collector] --> [Prometheus]
```

#### **Детальная схема**:
- **Shop API** → **Jaeger Collector** → **Elasticsearch**
- **CRM API** → **Jaeger Collector** → **Elasticsearch**
- **MES API** → **Jaeger Collector** → **Elasticsearch**
- **RabbitMQ** → **Jaeger Collector** → **Elasticsearch**
- **Jaeger Query** → **Elasticsearch** → **Jaeger UI**
- **Kibana** → **Elasticsearch** → **Analytics**

### **Автоматический мониторинг и алертинг**

#### **Мониторинг процесса заказа**:
1. **Order Lifecycle Tracking** - отслеживание жизненного цикла заказа
2. **Stuck Order Detection** - обнаружение застрявших заказов
3. **Error Pattern Analysis** - анализ паттернов ошибок
4. **Performance Monitoring** - мониторинг производительности

#### **Алерты**:
1. **Order Stuck Alert** - заказ застрял более 30 минут
2. **High Error Rate Alert** - высокий процент ошибок
3. **Slow Processing Alert** - медленная обработка
4. **Message Loss Alert** - потеря сообщений в RabbitMQ

#### **Автоматические действия**:
1. **Auto-retry** - автоматическая повторная попытка
2. **Escalation** - эскалация в команду поддержки
3. **Notification** - уведомления в Slack
4. **Ticket Creation** - создание тикета в системе

### **Обновленная схема с мониторингом** (зеленые элементы - мониторинг):
```
[Order Lifecycle Tracker] --> [Alert Manager] --> [Slack]
[Error Pattern Analyzer] --> [Alert Manager] --> [Ticket System]
[Performance Monitor] --> [Grafana] --> [Dashboard]
[Stuck Order Detector] --> [Auto-retry] --> [Escalation]
```

## Компромиссы

### **Ограничения трейсинга**:

#### **1. Производительность**:
- **Overhead**: 1-2ms на запрос
- **Memory**: +10-15% потребления памяти
- **Network**: Дополнительный трафик
- **Storage**: Большой объем данных

#### **2. Технические ограничения**:
- **Sampling**: Не все запросы трейсятся
- **Retention**: Данные хранятся ограниченное время
- **Cardinality**: Ограничения на количество уникальных трейсов
- **Latency**: Влияние на время ответа

#### **3. Бизнес-ограничения**:
- **Cost**: Дополнительные расходы на инфраструктуру
- **Complexity**: Усложнение системы
- **Training**: Обучение команды
- **Maintenance**: Поддержка системы трейсинга

#### **4. Проприетарные системы**:
- **MES Legacy**: Старая система может не поддерживать трейсинг
- **Custom Integration**: Требуется доработка
- **Vendor Lock-in**: Привязка к конкретному решению
- **Migration**: Сложность миграции

### **Когда трейсинг не поможет**:
- **Внешние системы**: Нет контроля над внешними API
- **Legacy системы**: Старые системы без поддержки
- **Network issues**: Проблемы на уровне сети
- **Hardware failures**: Отказы оборудования

## Безопасность

### **Внутренняя безопасность**:

#### **Аутентификация**:
- **LDAP/AD Integration** - интеграция с корпоративной системой
- **Role-based Access** - доступ на основе ролей
- **Multi-factor Authentication** - двухфакторная аутентификация
- **Session Management** - управление сессиями

#### **Авторизация**:
- **Support Role** - доступ к просмотру трейсов
- **Admin Role** - доступ к настройкам
- **Read-only Role** - только просмотр
- **Audit Role** - доступ к аудиту

#### **Защита данных**:
- **Data Encryption** - шифрование данных
- **Access Logging** - логирование доступа
- **Data Masking** - маскирование чувствительных данных
- **Retention Policies** - политики хранения

### **Внешняя безопасность**:

#### **API Security**:
- **API Keys** - ключи для доступа к API
- **Rate Limiting** - ограничение скорости запросов
- **IP Whitelisting** - белый список IP адресов
- **SSL/TLS** - шифрование соединений

#### **Network Security**:
- **VPN Access** - доступ через VPN
- **Firewall Rules** - правила файрвола
- **Network Segmentation** - сегментация сети
- **DDoS Protection** - защита от DDoS

### **Меры безопасности**:

#### **1. Аутентификация**:
- Только сотрудники с актуальной учетной записью
- Роль "Поддержка" для доступа к трейсам
- Роль "Администратор" для настройки системы

#### **2. Авторизация**:
- Доступ только к трейсам своей команды
- Запрет на изменение данных
- Аудит всех действий пользователей

#### **3. Защита данных**:
- Маскирование персональных данных
- Шифрование чувствительной информации
- Ограничение времени хранения

#### **4. Мониторинг**:
- Логирование всех действий
- Алерты на подозрительную активность
- Регулярные аудиты безопасности
